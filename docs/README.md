# OctoAcme Project Management Docs

This directory contains the project management processes, roles, and practices used by OctoAcme. It provides a shared source of truth for planning and delivering cross-functional work, supports onboarding, and helps the team apply a consistent, repeatable approach.

## Project management process summary

OctoAcme uses a lightweight, customer-focused, and iterative project management lifecycle:

1. **Initiation** — Validate the business need, define measurable outcomes, align stakeholders, identify risks and resources, and make a go/no-go decision before planning begins.
2. **Planning** — Turn approved initiatives into prioritized and estimated backlogs with acceptance criteria, milestones, release plans, a Definition of Done, and an initial QA approach.
3. **Execution and tracking** — Manage work on a project board, use small pull requests with CI checks and reviews, track progress and delivery metrics, and escalate blockers through defined levels.
4. **Risk management and communication** — Maintain a risk register, monitor dependencies, provide regular status updates, and escalate issues from the team through the Project Manager, Product Lead, and Sponsor as appropriate.
5. **Release and deployment** — Confirm acceptance criteria, CI and security checks, release notes, rollback planning, staging smoke tests, production verification, and stakeholder communications before and after deployment.
6. **Retrospective and continuous improvement** — Review what went well and what could improve after sprints, releases, milestones, or incidents; track a small number of owned action items and measure their impact.
7. **Roles and responsibilities** — Clarify how Project Managers, Product Managers, Developers, QA/Testing, and stakeholders contribute to successful delivery.

Quality assurance is built into the workflow through unit tests for new logic, integration tests where appropriate, end-to-end smoke tests for critical flows, security scanning in CI, manual QA when needed, and pull-request review. Work should meet acceptance criteria and the Definition of Done before release. Release validation includes staging smoke tests, production verification, rollback planning, and stakeholder communication.
